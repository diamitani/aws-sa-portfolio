LP 08 AWS Leadership Principle

Insist on the Highest Standards

"Leaders have relentlessly high standards — many people may think these standards are unreasonably high. Leaders are continually raising the bar and drive their teams to deliver high-quality products, services, and processes. Leaders ensure that defects do not get sent down the line and that problems are fixed so they stay fixed."

S Situation

I was building custom AI agents and web apps using coding harnesses and LLM chain prompting, and I kept hitting the same defect: a single one-shot prompt, no matter how well-written, produced inconsistent output because the model lacked structured context.

⚠️ My work at Atlas had already taught me that every serious project needed a defined PRD, architecture, and project plan before build—but most AI-assisted development skipped that discipline entirely and went straight from a vague prompt to code, letting quality problems get baked in from the start.
T Task

I set out to fix that root cause rather than patch around it project by project.

My goal was to build a repeatable framework that would force every build—agent, web app, or automation—through the same rigorous intent-extraction and documentation process I used at Atlas, so defects from unclear requirements never made it downstream into the actual build.

A Action
01

Intent Classification

Built a classification method that breaks down a user's prompt into its core entities—people, places, things—then runs each entity through a retrieval method I call RAG-DAL to pull relevant best practices.

Example: A prompt like "I want to build a sneaker website in Seattle" would trigger research into ecommerce platforms, Seattle sneaker culture, and shoe retail patterns.

02

Research-Enhanced Rewriting

That research rewrites the original prompt into a sharper, better-instructed version before it ever reaches the build LLM.

03

Non-Negotiable Outputs

For outputs, I held the bar at what I knew from Atlas was the minimum for a defensible build: every project had to produce a PRD, an architecture diagram, and a project plan, no exceptions.

04

Framework Packaging

Packaged this entire process into a runtime I named ROSTR (Runtime, Orchestration, State, Tools, References) and a skill called PAL (Prompt Abstraction Layer), which enforces the sequence: extract intent, enrich with RAG-DAL, generate a jobs-to-be-done report, prioritize next steps with a framework I built called NPAO, and always output a complete Build Package—never a partial one.

05

Benchmark Validation

Rather than ship this on faith, I held it to a measurable bar. I ran the framework through 11 benchmark tasks and published the results.

+15.2% Task Completion vs Baseline
+19.7% Output Coherence vs Baseline
06

Model Selection Matrix

Ran a second evaluation across five local LLMs—testing each on PAL compilation, NPAO routing, RAG grounding, Hub synthesis, and full pipeline orchestration—and used the results to define which model should handle which job:

  • deepseek-r1:14b scored 85.1% → default for reasoning and synthesis tasks
  • qwen2.5-coder:14b scored 84.4% at less than half the latency → default for balanced day-to-day use
  • A model scoring only 57.7% was flagged as not recommended and excluded from the routing table entirely
07

Retrieval Validation

On the retrieval side, I benchmarked RAG-DAL's multi-pass, source-credibility-weighted retrieval against single-pass retrieval:

92% RAG-DAL Confidence
68% Single-Pass Confidence
R Result
Published GitHub Repo + Research
6 Pillars WAF Aligned
0 Silent Defects

ROSTR is now a published, testable framework—available as a GitHub repo, a live platform, and peer-reviewed research—built against AWS's own Well-Architected Framework principles.

Because every routing and retrieval decision is backed by a benchmark score rather than assumption, the framework won't advance a build past a model or method that fails to clear its bar—which is what turned a defect I kept seeing repeatedly (unstructured prompts producing unreliable output) into a fixed, enforced process that can't quietly recur.
